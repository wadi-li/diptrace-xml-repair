# Ремонт библиотек DipTrace XML (.libxml / .elixml)

[Открыть онлайн](https://wadi-li.github.io/diptrace-xml-repair/) · [Скачать HTML](diptrace-xml-repair.html) · [Локальный сервер DipTrace-XML-Repair.cmd](DipTrace-XML-Repair.cmd) · [Сценарий индексации 3D-моделей](dt-models3d-index.cmd)

Автономный HTML-инструмент: `diptrace-xml-repair.html` (открыть в браузере, интернет не нужен).

- Терпимый разбор повреждённого XML (обрезка, незакрытые теги, NUL, неэкранированные & <), запись в стиле DipTrace (CRLF, BOM, без отступов; без правок — побайтно тот же файл).
- Проверки по спецификациям DipTrace: https://diptrace.com/support/tutorials/xml_specs_PattEdit_html/ , https://diptrace.com/support/tutorials/xml_specs_CompEdit_html/
- Исправление отмеченного → `<имя>.fixed.<ext>` + журнал CSV (`;`, UTF-8 BOM).
- Поиск причины зависания делением пополам (части A/B с новым Name/UID32), варианты «без 3D/полей/категорий/RecoveryCode/…».
- Проверка наличия 3D-моделей по выбранным папкам.

Сборка: `python3 build.py` (src/*.js + src/app.html → diptrace-xml-repair.html; src/server.ps1 → DipTrace-XML-Repair.cmd). Тест: `node test/t.js <файл.libxml|.elixml>` — проверка, исправление и повторная проверка в Node.js.

## Полный режим: локальный сервер

`DipTrace-XML-Repair.cmd` положить в одну папку с `diptrace-xml-repair.html` и запустить двойным щелчком. Это Windows PowerShell 5.1 (входит в Windows), установка и права администратора не нужны. Сервер слушает только `127.0.0.1:8765` (при занятости — следующие порты до 8780), открывает инструмент в браузере и принимает запросы только со своей страницы (одноразовый токен, проверка Host/Origin). Остановить — кнопкой «Остановить сервер» или закрыв окно консоли.

В этом режиме добавляется раздел «Папки и базы»:

- Подключено в DipTrace: чтение `C:\ProgramData\DipTrace\Data_Unicode\libgroups.dat` и `libgroups_var.dat` (переменные `%mylibs%`, `%my3dmodels%`, подключённые библиотеки), открытие всех подключённых XML одной кнопкой. Сброс групп библиотек (известное средство при зависании, [форум DipTrace](https://diptrace.com/forum/viewtopic.php?t=16780)) — переименованием в `*.dtr-bak-<время>` при закрытом DipTrace, с восстановлением.
- Мои папки с библиотеками: системный диалог выбора папки или путь вручную, поиск `.libxml/.elixml` с подпапками, статус каждой базы, «Проверить все», сводный отчёт CSV.
- Запись результатов рядом с исходником: `<имя>.fixed.<ext>`, отчёты CSV, части поиска зависания — в подпапку `dtr-test`. Кнопка «Исправить и заменить исходный» делает резервную копию `<имя>.bak-ГГГГММДД-ччммсс.<ext>` и предупреждает, если DipTrace запущен.
- 3D-модели проверяются автоматически по папкам из `%my3dmodels%` и `<DipTrace>\models3d`, сценарий индексации не нужен.

Настройки сервера: `%APPDATA%\dt-xml-repair\config.json`. Ответы передаются с `Transfer-Encoding: chunked`: фильтры трафика вроде AdGuard встраивают скрипт в HTML даже на 127.0.0.1 и без этого обрезают страницу.

Если Windows SmartScreen предупредит о файле из интернета — «Подробнее» → «Выполнить в любом случае» или снять флажок «Разблокировать» в свойствах файла.

## Автоматическая проверка 3D-моделей (без сервера)

`dt-models3d-index.cmd` положить в папку с `diptrace-xml-repair.html` и запустить: он запишет `dt-models3d-index.js` (имена файлов и признак «только в облаке» OneDrive из папок `C:\Users\limar\OneDrive\DipTrace\models3d` и `C:\Program Files\DipTrace\models3d`). Инструмент подхватывает его сам при открытии и по кнопке «Проверить 3D-модели». Сценарий с другими путями можно скачать из самого инструмента.

Онлайн-версия работает так же, файлы обрабатываются только в браузере и никуда не отправляются. Автоматическая проверка 3D-моделей по `dt-models3d-index.js` работает только в локальной копии HTML, лежащей рядом с этим файлом; онлайн доступен разовый выбор папок вручную.
